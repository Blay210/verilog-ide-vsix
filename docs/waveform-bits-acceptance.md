# 버스 비트 펼치기 — 구현과 수용

2026-10-05. 파형 UX 개선 중 버스의 개별 비트 표시를 구현했다. 전체 안정화 검증 완료가 아니다.

## 동작과 경계

- 버스 이름 앞 ▸/▾ 토글로 부모 버스 아래 개별 비트를 펼치고 접는다. 부모 버스 표시도 유지하며 자식은 0/1/X/Z로 읽는다.
- VCD 선언 범위에 따라 `[7:0]`과 `[0:7]`, 비영/음수 인덱스를 구분한다. 범위가 없거나 폭/다차원 범위가 맞지 않으면 `bit offset N`(LSB 기준 위치)으로 표시하고 선언 인덱스라고 추측하지 않는다.
- 편집기 독립 waveform 패키지의 busBits/bitValue/bitRow가 부모 채널을 투영한다. worker 요청은 기존 부모 신호 목록 그대로이며 자식용 채널을 추가하지 않는다. 비트가 바뀌지 않은 부모 변화는 자식의 edge에서 제외한다. BigInt 시각은 decimal string 그대로 유지한다.
- dense 창에서는 개별 bit edge를 추측하지 않는다. 부모 bus 활동 bucket을 보수적으로 표시하고 자식 값 hover에 parent activity 안내를 준다. 확대 후 정확한 bit 변화를 본다.
- 선택한 부모 최대32개는 그대로다. 개별 버스 최대128비트, 전체 추가 bit 행 최대128개. 초과 시 접힘 유지/이유 안내. 복원 시 지원하지 않거나 예산을 넘는 확장은 안내하고 접는다. 실수 버스는 확장하지 않는다. 가상화 구현은 아니다.
- 자식은 부모 바로 아래 선언 순서를 따른다. 부모를 옮기면 자식도 함께 이동한다. 자식만 따로 드래그/선택/색상 지정하는 기능은 아직 없다. 자식에서 커서를 조작할 수 있지만 Edge/스타일 포커스는 부모 기준이다. 별도의 개별 bit edge 탐색은 후속이다.
- ViewSignal.expanded는 version1 보기의 선택적인 boolean 필드다. 기존 보기 읽기, 새 저장/기본 보기/적용/누락 신호 보존을 지원한다. 과거 버전 앱은 알 수 없는 필드를 보존하지 않을 수 있으므로 하위 버전으로 재저장하는 호환까지 보장하지 않는다. 현재 편집기 상태에도 경로로 저장한다. 부모 포함 해제 시 자식과 확장 상태를 같이 제거한다.

## 검증 결과

관련 자동32 PASS / 0 fail / 0 skip. 범위 방향·음수/비영 범위·모르는 범위 fallback, X/Z와 큰 timestamp 투영, 다른 비트 변화의 제거, dense 보수성, 보기 JSON/legacy/누락 보존/잘못된 flag 거부를 검증했다. 실제 번들 이벤트로 펼침/접힘/재init 복원/부모 제거/전체128 행 초과 차단을 검증했다. 기존 worker·cursor 연동·저장 보기·정렬·ruler 회귀도 통과. 타입 검사와 개발 빌드 통과. VSIX/설치 없음.

물리 UI: VS Code1.140.0, 격리 rQSqPW profile, project-peer의 `.rtl/runs/ui-wave-ux/wave.vcd` 합성 자료(4신호11변화41.2ns). data[7:0] 토글로8자식, [0]의10~20ns pulse와[1]의20ns 이후 high를 확인했다. 총4부모/8자식 상태에서도 A4.556ns 유지. valid 클릭 → Tab으로 ready 초점 → Shift+Space로 두 행 범위 선택 → 마우스 드래그로 버스 위에 valid,ready 순서 유지 이동을 확인했다. 저장 보기 `비트 펼침 검증` 저장, Reload 후 펼침/순서/커서 유지, 다시 접어4행 복귀와 Unsaved changes 표시 확인. 개발 창 exit0.

Shift+키보드 선택과 물리 묶음 드래그는 수용했지만 Ctrl/Shift+마우스 조합은 자동 이벤트 검증 범위다. 저장 보기의 기본 지정 후 별도 새 run 자동 적용 및 Code 재시작 수용은 이번 UI 범위에 포함하지 않는다. native simulator 실행 성공과 합성 파형 수용을 구분한다. 초기 fake DOM 테스트가 onchange 속성을 잘못 호출해 실패했으며 실제 등록 이벤트(change)로 수정 후 최종 통과했다.
